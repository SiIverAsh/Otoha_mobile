# 安卓 0.2.0 开发版

更新：2026-11-15（Asia/Shanghai）。此文描述代码与实测状态；产品完整验收仍按仓库根目录的交接文档执行。

## 本轮已实现

- Kotlin / Compose / Media3 工程，固定 Gradle Wrapper 与发行包 SHA-256，Android 8.0 起，compile/target SDK 36。
- 双源独立按需分页与错误状态；ASMR18 分类与规范化作品链接；作品元数据、封面、目录/版本及文件选择。
- ASMR.one JSON 镜像降级、递归目录、同目录字幕配对；ASMR18 HTML 静态解包、多文件 HLS 和章节。没有执行远端 JavaScript。
- MediaSessionService 后台播放器、系统媒体会话、音频焦点、拔耳机暂停；HLS 主/子清单、分片与密钥共用对应源的请求头配置。
- 同一目录队列、上下曲、seek、倍速、章节跳转、LRC/SRT/VTT/ASS/SSA 字幕与 15/30/60 分钟睡眠定时。
- 版本化原子 JSON 保存本地收藏、最近作品、最后队列/索引/位置/倍速；恢复时刷新源 URL，并严格匹配曲目稳定身份与目录，找不到时要求重新选择。
- 分级过滤同时作用于浏览、详情、收藏、最近、续播与当前播放器。未知分级默认隐藏。
- 无痕以队列 token 撤销个人记录权限；退出无痕、旧回调、清历史和链接重试均不能恢复已撤销的写入权限。普通封面缓存独立管理。
- ASMR.one 自动/预设/自定义 HTTPS 镜像设置、清理封面缓存、清理历史；个人数据云备份与设备迁移均排除。
- 本地未捕获 Java 异常报告、再次启动时的诊断恢复页，以及设置页复制诊断信息。报告最多 64KiB，包含设备/SDK/应用版本与异常堆栈，存于本机且不自动上传；写入后仍交由原异常处理器处理，不自动重启。
- 依据 Xiaomi 15 Pro / Android 16 真机报告，修正 ASS 覆盖标签正则末尾裸右花括号导致的 Android ICU 编译失败；版本升为 0.1.2（versionCode 3），用户已确认正常启动且可获取 ASMR18 目录。详见 [启动异常记录](startup-crash-2026-11-15.md)。
- GitHub Actions 配置不请求音源的自动化测试、Lint、Debug APK 产物；尚未提交或推送，未执行远端 CI。Robolectric 首次运行会按需下载 SDK 运行时依赖，需要网络或预热缓存。

## 本地异常诊断流程

Application 尽早安装未捕获异常处理器，音源客户端、个人数据与媒体入口延迟初始化。发生未捕获 Java 异常时，尽力原子保存最近一份报告至 `noBackupFilesDir/last-crash-report.txt`，再调用原处理器。报告包含厂商、型号、Android 版本/SDK、PackageManager 读取的应用版本、时间、线程与异常链；UTF-8 文件上限为 64KiB，超长会标记截断。

用户重新打开应用时，如存在报告，先显示“上次运行出现异常”。此页不创建 MainViewModel、MediaController 或音源请求。用户可以复制报告；点击“清除并重试”后才进入正常界面。正常设置页也提供“复制诊断信息”，无异常记录时仅提供设备与版本信息。报告只保存在本机，复制时进入系统剪贴板，不自动上传。

此流程不保证记录原生崩溃、ANR 或系统终止进程。本次 Xiaomi 15 Pro 的报告已明确指向字幕解析器静态初始化；此前两项 Robolectric 测试通过没有覆盖设备 ICU 正则行为，不能据此宣布真机问题已修复。
